## 3. 用户新增需求：网文“反和谐”

这里的“网址”按上下文理解为“网文正文”；真实 URL 仍属于不可修改的保护值。如 DSH 对这一点存在歧义，必须在报告中明确列为待确认项，不能擅自改 URL。

需覆盖的污染类型：

- 在词语中插入标点、空格、Unicode 符号或零宽字符，例如 `杀*人`、`杀·人`、`杀 人`；
- 同长度的错字、同音字、形近字或平台替换字；
- 个别字符被删除后的有限恢复。

安全边界：

- 仍然禁止润色、扩写、续写、改剧情、改事实、改专名及任意敏感内容重写；
- URL、长数字、哨兵的值、数量与顺序必须逐字保持；
- “删除插入噪声”只允许已定义的有限字符类别和有限长度，不可把任意符号都当噪声；
- “恢复缺字”不得开放任意空位置插入。只能在精确上下文锚定、长度极小（建议最多 1–2 个 code point）、结果唯一且所有保护项/结构校验仍通过时考虑；重复或歧义锚点必须整章失败关闭；
- 当前 `typo` / `anti_theft` 的等核心字符数约束可覆盖部分等长替换，但不能直接覆盖缺字恢复。任何协议扩展都必须先有反例测试，再改生产代码；不得为了让当前模型过关而整体放宽 validator。

## 4. DSH 唯一执行顺序

### 第一步：补齐可诊断但不泄密的失败分类（当前最高优先级）

1. 阅读《AI正文净化功能计划书.md》、本任务书、阶段 C/D 任务书和实施报告，以及当前 AI 模块、`ReadBook`、`ReadBookActivity` 的真实 diff。
2. 复用现有 `AiFailureCode`，在失败状态首次落定时记录一次固定前缀、枚举名与可选块号；不得记录异常 message、请求/响应体、正文片段或对象 `toString()`。优先用可注入的无内容 reporter 并用 JVM 测试证明，避免 Activity 重组导致重复日志。
3. UI/测试/日志只显示安全分类和块序号，不得显示 API Key、Authorization、请求/响应正文、章节内容、书名、书源、Cookie 或真实 URL。
4. 用合成 fixture 和 Fake Provider 覆盖 Provider、输出校验与章级失败的分类/块号；先在真机确认当前失败码，再决定是否修改 prompt/schema/解析。不要凭旧版 `AiFldbg` 日志猜测。

### 第二步：让真实模型输出与严格契约可兼容

1. 优先修 prompt/schema/解析的确定性问题，不先放宽 validator。
2. 检查模型是否把 UTF-16 下标、Unicode code point 下标或文本锚点混用；本地协议必须只有一种明确定义，并有 emoji、补充平面 CJK、组合字符和零宽字符测试。
3. 可评估的安全候选：当模型返回的 `original` 在当前块中是精确且唯一的子串时，本机可重建数值范围；若不唯一、越界、交叠、触碰哨兵或其他约束失败，则整章回退。此项只是候选方案，必须先写正反例证明不会误定位，不能盲目实现。
4. 不得继续静默降低单块上限来掩盖问题，也不得把空 content 当作“无编辑”成功。任何有限重试必须有严格次数上限、只针对明确可恢复分类，并加入调用次数/不缓存反例。

### 第三步：收敛反和谐协议与测试

至少加入以下正反例：

- 插入噪声：ASCII 标点、中文标点、Unicode Symbol、普通空格、不换行空格、零宽字符；只允许明确白名单或有界规则；
- 等长替换：单个/少量错字可修，正常专名和连续长句改写拒绝；
- 缺字恢复：唯一精确上下文、最多 1–2 code point 的候选可通过；任意空位置、重复上下文、跨块、超长插入或无法证明唯一性必须拒绝；
- `https://example.com/a?x=123`、普通数字、长数字和哨兵全部保持；
- 编辑重叠、顺序错误、块 ID 错、回显整段、Markdown 包裹、额外解释、截断 JSON 均失败关闭；
- 任一块失败后不请求后续块、不缓存 Completed，原文继续可读。

如果经过反例论证仍无法安全支持“缺字恢复”，第一版应明确降级为“不支持并失败关闭”，不能用宽松插入换取表面成功率。

### 第四步：完成自动化与真机回归

自动化命令（PowerShell）：

```powershell
$env:GRADLE_USER_HOME = 'D:\gradle_home'
.\gradlew.bat :app:compileAppDebugKotlin :app:testAppDebugUnitTest --console=plain
.\gradlew.bat :app:lintAppDebug --console=plain
git diff --check
```

真机至少覆盖《AI正文净化功能计划书.md》§11.2，并特别补充：

1. 阅读页无浮动 AI 控件、正文无遮挡，AI 入口只在三点菜单；
2. 菜单状态与点击动作相符，不误跳设置；
3. 重进当前书/章节会正确恢复或重启处理，不出现“重试无反应”；
4. 正常真实章节能到“AI 正文已就绪”，仅在用户主动切换后从章首显示候选，原文可立即切回；
5. 校验失败、断网、超时、认证失败、限流、取消、切章、旋转、退后台均不白页、不串章、不无限重试；
6. 缓存命中与清理、阅读位置、替换净化、朗读、搜索、导出、本地 TXT/EPUB、漫画和图片章节无回归；
7. 真实 URL、数字和正常专名在反和谐样本中保持不变。

如果 DSH 无法操作真机，只能提交“代码与 JVM review”，必须把真机项标为未执行，不得宣布阶段 E 或发布验收通过。
