## 它在本次 P0 里顶的是哪一条

《书源与解析优化计划书》§13 第 2 条要的是：

> 「多出符号」和「跳行」的实际截图或脱敏前后文本

这份语料里 **A 类（字符污染）** 与 **B 类（跳行与内容缺失）** 是与这两样对应的成对
「输入 / 预期」文本，不需要截图。但**它只补上了一部分**，逐条核对如下：

| | 状态 | 依据 |
| --- | --- | --- |
| **B01** | ✅ 满足 | 语料同时给了原始 HTML（`<p>他走到山门前。</p>…`）与产物，**可离线复现** |
| **B 类其余** | ⚠️ 部分 | 有输入 / 预期，但没有原始 HTML、没有书源标识 |
| **A 类** | ❌ **不满足** | 只有一行「AI 实际收到的文本」 |

**A 类为什么不满足**：语料文档 §3 的模板自己定义了 `input: AI 实际收到的文本` ——
那是**链路末端**的一行字，不是 §13 要的「脱敏**前后**文本」。没有原始 HTML、没有书源、
没有四段快照，就没有任何办法判定那个字符是站点原文、书源规则写的、还是通用层写入的。
11 类归因里有 46 条送对抗验证、**34 条被推翻**，压垮判定的是同一个理由：
**排除法缺了通用层与展示层这两整支**。详见 [`../语料归因.md`](../语料归因.md) 第四节。

所以 A/B 类的正确标记是 **「样本不可回溯，需真实链路四段快照」**，
而不是「§13 第 2 条已满足」。

## 怎么用、不怎么用

用户交付时的原话是「**只看样例，不看规则**」。落到本次工作里：

- **用的**：每个条目的「输入」与「预期」文本——它们是这次分析的事实依据；
- **不用的**：文档 §1 的决策定义（`FIX`/`KEEP`/`UNCERTAIN`/`FALLBACK`）、§2 的通用验收规则、
  §4 的统计指标。**这些是面向 AI 后处理层的规则**，而 P0/P1 的范围是解析层与展示层，
  且 §14.2 明确本批不碰 AI 分支。把那份规则表当成实现规格会直接越界。

换句话说：这份文档在本仓库里的角色是**样本来源**，不是**需求文档**。

## 脱敏状况

收录前已核查：

- 全文**零命中** `cookie` / `authorization` / `token` / `header` / `Bearer` / `password`；
- 全文只有一个 URL：`https://example.com/read?id=12&page=3`（H04，保留域）；
- 其余站点名一律是占位（`某某小说网`、`xx.com`、`www.example.com`）。

因此它满足 §3.4 的入库边界（脱敏统计、合成夹具）。**若你希望它不入库，删掉本目录并在
`.gitignore` 加一行即可**，本次分析结论不依赖它留在仓库里。
