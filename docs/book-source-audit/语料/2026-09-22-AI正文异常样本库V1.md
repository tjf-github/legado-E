# Legado AI 正文处理异常样本库 V1

> 用途：测试 Legado 在线正文经过书源解析、净化、分批和 AI 后处理后的正确性。  
> 原则：有把握才修复；无法从现有文本恢复的内容不得编造。  
> 范围：删除“AI 处理异常”独立分类，保留 11 类正文与解析异常；AI 输出的合法性由统一验收规则负责。

## 1. 决策定义

| 决策 | 含义 |
|---|---|
| `FIX` | 异常明确，允许修复 |
| `KEEP` | 原文合法，必须保持 |
| `UNCERTAIN` | 疑似异常但证据不足，保留原文并记录 |
| `FALLBACK` | 输出不可接受，回退原文或交由解析层处理 |

## 2. 通用验收规则

- 不新增人物、动作、对白、设定或情节。
- 不把正文概括、润色或改写成另一种文风。
- 不修改人名、地名、功法名、书名等专有名词，除非上下文证据充分。
- 不输出说明、前后缀、Markdown 围栏或“修复后的内容如下”等附加文本。
- 整行、整段或章节缺失且无可靠原文时，不允许续写补全。
- 保留合法的诗词分行、聊天记录、系统面板、代码、公式、URL、Emoji 与特殊符号。
- 跨批次处理时，边界上下文只用于判断，不得重复写入输出。
- 建议同时保存：原始 HTML、Legado 解析结果、AI 输入、AI 输出、最终展示文本。

## B. 跳行与内容缺失

### B01 · 可从原始 HTML 恢复的跳行

- 原始 HTML：`<p>他走到山门前。</p><p>守门弟子拦住了他。</p><p>他取出令牌。</p>`
- 解析输入：`他走到山门前。\n他取出令牌。`
- 预期：从原始 HTML 重新解析为三段完整文本。
- 决策：`FALLBACK`
- 测试点：这是解析层丢失，不应要求 AI 猜出中间内容。

### B02 · 无来源的整行缺失

- 输入：`他走到山门前。\n他取出令牌。`
- 预期：保持现有文本，不补写守门过程。
- 决策：`UNCERTAIN`
- 测试点：AI 无法可靠恢复从未收到的文本。

### B03 · 半句截断

- 输入：`他缓缓拔出长剑，剑锋指向\n\n下一刻，天地变色。`
- 预期：保持原文并报告疑似截断。
- 决策：`UNCERTAIN`
- 测试点：不能凭空补全剑锋指向的对象。

### B04 · 批次切分导致断句

- 前批末尾：`她伸手接过那封`
- 后批开头：`信，沉默了很久。`

- 决策：`FIX`
- 测试点：拼接后不得遗漏或重复“那封/信”。

### B05 · 疑似章节缺失

- 输入：`第十二章 夜雨\n……正文……\n第十四章 归途`
- 预期：不生成第十三章；交由章节目录或书源层核验。
- 决策：`FALLBACK`
- 测试点：章节编号不连续不是续写依据。

- 预期：不猜测对白；触发重新抓取、重新解码或回退原文。
- 决策：`FALLBACK`
- 测试点：多个异常叠加时仍禁止编造。

## 4. 建议统计指标

| 指标 | 含义 |
|---|---|
| 明确异常修复率 | `FIX` 样本中输出完全符合预期的比例 |
| 正常文本误改率 | `KEEP` 样本中发生任何非必要变化的比例，越低越好 |
| 不确定样本克制率 | `UNCERTAIN` 样本中未擅自补写或改写的比例 |
| 回退正确率 | `FALLBACK` 样本中成功拒绝错误结果并回退的比例 |
| 内容保全率 | 输出相对输入发生的非目标删除、增加或顺序变化比例 |

## 5. 后续扩展规则

1. 实际阅读中出现新异常，先保存完整链路数据，再判断归类。
2. 已导致线上处理错误的案例必须加入回归集，不能只记录描述。
