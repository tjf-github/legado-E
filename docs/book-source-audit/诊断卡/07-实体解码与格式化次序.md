# 诊断卡 07 · 实体解码排在 HTML 格式化之后

> 本卡由语料归因的**完备性批评**发现：用户给的语料 C04（多余空行）与 C06（混合换行符）
> 在归因里判成了「无法判定 / 站点原有文本」，但通用层自己就能造出这两种形态。
> 诊断卡模板见 `TEMPLATE.md`；本卡是**问题类卡**（同 05、06），不绑定单个书源。

## 1. 现象

站点源码里写的是实体形式的换行与空白 —— `&#10;`（LF）、`&#13;`（CR）、`&#160;`（NBSP）、
`&#12288;`（全角空格 U+3000）—— 阅读时表现为**多余空行**、**混合换行符**或**行首缩进异常**。

## 2. 机制（一行代码的顺序问题）

`app/src/main/java/io/legado/app/model/webBook/BookContent.kt:244-247`：

```kotlin
content = HtmlFormatter.formatKeepImg(content, rUrl)   // 244 内置净化格式化
if (content.indexOf('&') > -1) {                       // 246
    content = StringEscapeUtils.unescapeHtml4(content) // 247 实体解码
}
```

顺序是**先格式化、后解码**。而 `HtmlFormatter` 里管换行与空白的正则只认真实字符、不认实体：

| 正则 | 位置 | 认什么 | 漏什么 |
| --- | --- | --- | --- |
| `nbspRegex = (&nbsp;)+` | `HtmlFormatter.kt:9` | **只认具名** `&nbsp;` | `&#160;`、`&#12288;` |
| `indent1Regex = \s*\n+\s*` | `HtmlFormatter.kt:20` | 真实 `\n` 序列 | `&#10;`、`&#13;` |
| `indent2Regex` / `lastRegex` | `HtmlFormatter.kt:21-22` | 行首/行尾真实空白 | 同上 |

于是 `&#10;` 在格式化阶段**根本不是换行**，躲过 `indent1Regex` 的归一（那条正则会把 `\n+` 收成
`"\n　　"`），解码后才变成真换行 —— **这批换行从此不再经过任何归一化**。

### 已实测复现（本地复刻 Kotlin 正则链，无需联网）

| 输入 | 格式化后 | 实体解码后 | 换行数 |
| --- | --- | --- | --- |
| `他推开门。&#10;&#10;&#10;&#10;屋内空无一人。` | 原样不变 | `他推开门。\n\n\n\n屋内空无一人。` | 0 → 0 → **4** |
| `他推开门。&#160;&#160;屋内空无一人。` | 原样不变 | 变成 U+00A0 ×2 | — |
| `他低声说：&ldquo;走吧。&rdquo;&nbsp;随后转身离开。` | `&nbsp;` 已收成普通空格 | 引号正确解码 | 0 → 0 → 0 |

第一行正是语料 **C04**；`&#13;` 同理产出 **C06** 的 `\r`；U+00A0 正是语料 **J06 全角半角混排**那一类。

### U+00A0 的修补还带系统版本条件

`ContentProcessor.kt:32` `private val isAndroid8 = Build.VERSION.SDK_INT in 26..27`，
`:205 if (isAndroid8) { mContent = mContent.replace(' ', ' ') }`。
**只有 Android 8.0/8.1 会把 NBSP 换回普通空格**，其余版本原样保留。

`EncodingDetect` 猜测」三条 charset 分支。选错就得到语料 J02 的 `浠栨帹寮€浜嗛棬銆俙`
