# 书源兼容不变量（P0 冻结）

本文件把《书源与解析优化计划书》§6 B2 的「不得改坏」条目落成可对照的 id。
每条 id 有**正例**（必须成立）与**反例**（出现即违规），P1 录制 golden 输出时按 id 建断言。

## 怎么用

1. `case-*.json` 的 `invariants` 列出该用例覆盖的 id。
2. P1 跑通 `BookContent` → `ContentProcessor` 链路，把输出录成 golden。
3. golden 只固定**当前行为**。改 P3 时若 golden 变了，先按本表逐条判断是「修好了」还是
   「改坏了」——本表是判断依据，golden 不是。

## 标注约定

- **【已核实】**：依据是项目内可读的代码，已逐行确认。
- **【待录制】**：行为取决于 jsoup 解析等运行期环节，本次只做静态阅读，P1 录制时才确定。
  这类条目的不变量写成「改动前后必须一致」而不是「必须等于某值」。

## A. 换行与块级标签

依据 `HtmlFormatter.kt` 的 `wrapHtmlRegex = </?(?:div|p|br|hr|h\d|article|dd|dl)[^>]*>`（→ `"\n"`）。

| id | 正例（必须成立） | 反例（出现即违规） | 状态 |
| --- | --- | --- | --- |
| `INV-FMT-BLOCK-1` | 每个块级标签（`div`/`p`/`br`/`hr`/`h1`…`h\d`/`article`/`dd`/`dl`）无论开闭、无论带多少属性，都变成一个换行 | 某个块级标签被整段删除而**没有**留下换行，导致两段文字粘连成一行 | 【已核实】 |
| `INV-FMT-BLOCK-2` | 块级标签**自身**被替换成换行，标签内的文字保留 | 标签被当普通标签删掉（走 `otherHtmlRegex`），换行消失 | 【已核实】 |
| `INV-FMT-STRIP-1` | 非块级、非 img 的标签（`b`/`i`/`a`/`span`/`font`/`script`…）被整体删除，**只删标签不删文字** | 连标签内的文字一起删掉 | 【已核实】 |

> `INV-FMT-BLOCK-2` 的反例正是 P3 最容易踩的坑：`wrapHtmlRegex` 必须在通用删标签正则
> **之前**执行，顺序一颠倒，所有换行都会消失。

## 已知的取舍：缩进 vs 诗歌

`INV-FMT-INDENT-1`（把连续换行压成「换行 + 两个全角空格」）与 `INV-POEM-2`
（诗歌依赖空行分组）在现有实现下**必然冲突**，`case-06` 冻结了冲突后的现状。

本文件**不做取舍判断**。P3 若要改，必须先有 `case-06` 的录制结果，并在改动说明里
写明对哪一类书源的影响面（`case-01` / `case-03` / `case-08` 提供普通文本、分页、
正常标点三组对照）。

## 与 §6 B2 的对应

§6 B2 要求「正常标点、诗歌空行、相邻图片、特殊 HTML、已有替换规则」五项都有对照：

| §6 B2 条目 | 覆盖用例 | 不变量 |
| --- | --- | --- |
| 正常标点 | `case-08-punctuation` | `INV-PUNCT-1` … `INV-PUNCT-4` |
| 诗歌空行 | `case-06-poetry-blank` | `INV-POEM-1`、`INV-POEM-2` |
| 相邻图片 | `case-04-inline-img`、`case-05-pure-image` | `INV-IMG-ADJACENT-1`、`INV-IMG-COUNT-1` |
| 特殊 HTML | `case-01-html-basic` | `INV-FMT-BLOCK-*`、`INV-FMT-ENTITY-*`、`INV-FMT-COMMENT-*` |
| 已有替换规则 | `case-07-existing-replace` | `INV-REPLACE-1` … `INV-REPLACE-4`、`INV-REPLACE-TRIM-*` |

## 与 §6 B2 之外的补充

`case-09` 与 `case-10`（2026-09-22 补）不对应 §6 B2 的任何一项，来自两个实际发现的缺口：

| 用例 | 来源 | 不变量 |
| --- | --- | --- |
| `case-09-title-in-body` | 用户追问「正文出现标题」 | `INV-TITLE-DEDUP-1` … `-3`、`INV-TITLE-KEEP-1`、`-2`、`INV-TITLE-DISPLAY-ONLY-1` |
| `case-10-entity-newline` | 语料归因发现的实体解码次序 | `INV-ENTITY-ORDER-1` … `-3`、`INV-ENTITY-DECODE-ONCE-1` |

两条都带**未决项**：`case-09` 的方向冲突（K 节末），`case-10` 与语料 G02
「实体只解码一次」的边界（L 节末）。**P1 录制 golden 时必须把这两处一并录下来**，
它们正是 P3 最可能改错的地方。
